| step | where | command |

- `make_filelists_Oct_22.sh` writes `Oct_22_DATA.txt` and
  `Oct_22_MC_<sample>.txt` for the ten POWHEG samples. The data of this pass
  sits in a skim directory,
  `DATA/PHOLEP/IonPhysics/crab_HiForest_IonPhysics_pORun2025_PromptReco_v1_PHOLEPSKIM_2026_10_22/`
  (user, 2026-10-25; earlier passes `DATA/IonPhysics<N>/HiForest_…`): task
  directories named `HiForest_*` or `crab_HiForest_*` are both accepted, only
  the skim `DATA_SKIM` (default `PHOLEP`) goes into the data list, and any
  other `DATA/<skim>/` is reported as unclaimed (two skims of the same runs
  would double count). Duplicate check per task directory. It reports every `HiForest_*` directory no table entry
  claims, with a suggested line: **the MiNNLO directory names were not known
  when the script was written**, so the first run prints them; add one line
  per MiNNLO sample to `SAMPLES_MINNLO` (`MiNNLO|<token>|MiNNLO_<name>`) and
  re-run. Exit status 1 until every directory is claimed or ignored.
- `run_all_hadd_Oct_22.sh` merges to `/eos/.../zheng/pO_2026_Oct_22/`.
- `download_Oct_22.sh` copies with `xrdcp -C adler32:source` to
  `~/pO_2026_Oct_22/`, via a `.part` file renamed on success; re-running
  resumes. No disk-space check (user: "don't worry about space").
- Tested 2026-10-25 on a fake production tree (bash 3.2): data from two PDs
  with a resubmitted task flagged, the ten POWHEG lists, low-mass DY ignored,
  a MiNNLO directory reported as unclaimed and listed once its line was added.
  The hadd and download scripts are syntax-checked only (no EOS access from
  here: the Kerberos ticket had expired).

- [ ] **What SC collection was stored:** collection name, E_T threshold, |η|
